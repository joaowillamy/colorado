# Guardrails: segurança além do prompt / Guardrails: security beyond the prompt

## EN

### What it is
Amazon Bedrock Guardrails enforce safety policies, filter sensitive information, and control the content of both the input (what the user sends) and the output (what the model generates).

### Why it matters
Not everything should reach the model. Not everything should be generated by it. Users type what they should not (for example, a credit card number), and models can generate what they should not. Security should not rely on a prompt instruction alone, because a prompt can be ignored or bypassed. It needs to be part of the architecture.

### Simple example (illustrative)
A user writes: "my card is 4111 1111 1111 1111".
- Without a guardrail: the number reaches the model, the logs and the conversation history.
- With a guardrail: the message is blocked before the model. Nothing is generated, and no model tokens are charged for that input.

### How it works in this assistant
- The guardrail is configured in Amazon Bedrock, outside the prompt, and attached to every Converse API call with tracing enabled.
- Policies in use: content filters (hate, insults, sexual, violence, misconduct), prompt attack detection on the input, and blocking of credit and debit card numbers.
- When the guardrail intervenes, the stop reason is guardrail_intervened. A pre-defined block message is sent to the user, and the blocked question is NOT saved in the history, otherwise it would be resent and blocked again on every turn.
- Blocking on input costs no generation. Blocking on output happens after the generation was already paid for.
- The guardrail can be turned off with an environment variable, for development.

## PT-BR

### O que é
O Amazon Bedrock Guardrails aplica políticas de segurança, filtra informação sensível e controla o conteúdo tanto da entrada (o que o usuário envia) quanto da saída (o que o modelo gera).

### Por que importa
Nem tudo deve chegar ao modelo. Nem tudo deve ser gerado por ele. Usuários digitam o que não deveriam (por exemplo, número de cartão de crédito) e modelos podem gerar o que não deveriam. A segurança não deve depender só de uma instrução no prompt, porque um prompt pode ser ignorado ou contornado. Ela precisa fazer parte da arquitetura.

### Exemplo simples (ilustrativo)
O usuário escreve: "meu cartão é 4111 1111 1111 1111".
- Sem guardrail: o número chega ao modelo, aos logs e ao histórico da conversa.
- Com guardrail: a mensagem é bloqueada antes do modelo. Nada é gerado e nenhum token do modelo é cobrado por essa entrada.

### Como funciona neste assistente
- O guardrail é configurado no Amazon Bedrock, fora do prompt, e anexado a toda chamada da API Converse com trace ligado.
- Políticas em uso: filtros de conteúdo (ódio, insultos, sexual, violência, má conduta), detecção de prompt attack na entrada e bloqueio de número de cartão de crédito e débito.
- Quando o guardrail intervém, o stop reason é guardrail_intervened. Uma mensagem de bloqueio pré-definida é enviada ao usuário, e a pergunta bloqueada NÃO é salva no histórico, senão seria reenviada e bloqueada de novo a cada turno.
- Bloquear na entrada não custa geração. Bloquear na saída acontece depois que a geração já foi paga.
- O guardrail pode ser desligado por variável de ambiente, em desenvolvimento.
